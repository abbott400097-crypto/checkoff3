Sources & demo details

Course topic: Data Representation → Data Compression → Run-length encoding (RLE), explicitly listed in the COMP211 Checkoff 3 instructions.

This is a deliberately small lossless format, not a BMP or PNG encoder. Each input pixel is a one-byte palette index. Each output pair is a one-byte count (1–255), followed by a one-byte color index. Longer runs split at 255. Image dimensions and the palette are known separately. All displayed sizes measure pixel-data payload only, excluding metadata. Rows in this toy image flatten into one stream, so a run may cross a row boundary.

Microsoft: Bitmap Compression describes RLE8 encoded pairs and the extra modes and markers real BMP files need.
DICOM: The RLE Algorithm describes a different RLE variant that also supports literal runs. These references support the principle, not a claim that our toy format implements either standard.

The C experiment rle_demo.c independently encodes and decodes the 32-pixel examples. It also checks 255-byte run splitting, empty input, output capacity, malformed input, and round trips. The live browser demo performs an encode/decode equality check after every change. Pixel artwork and animations are original HTML/CSS/JavaScript. No network resources are required to play the downloaded HTML.
